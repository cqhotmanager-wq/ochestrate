## 1. 系统总体说明

### 1.1 目标

该平台提供统一智能体能力底座，支持：

- 企业知识问答（RAG）
- 自动化任务执行（多智能体协同）
- 模型路由（本地模型 + 云模型）
- 工具中心与技能中心
- 上下文管理、摘要、短期/长期记忆
- 反馈学习与可观测审计

### 1.2 核心技术栈

- Web/API：FastAPI
- 多智能体编排：LangGraph
- 提示词模板：LangChain
- 文本分块：LlamaIndex
- 关系数据：MySQL
- 向量检索：Milvus

### 1.3 一期工程实现边界

- 已实现可运行的端到端骨架（可本地启动和联调）
- 外部系统（真实邮件/IM/OA）当前为可扩展接口与示例工具
- RAG 当前默认内存存储，Milvus 连接适配器已预留

## 2. 目录结构与模块功能

### 2.1 主要目录

- `app/main.py`：应用入口，启动 FastAPI 与后台任务 worker
- `app/api/v1`：API 路由层
- `app/orchestration`：多智能体编排服务
- `app/agents`：Planner/Retriever/Executor/Reviewer 四类 Agent
- `app/models`：模型 Provider 与路由
- `app/rag`：知识摄取与检索
- `app/memory`：短期/长期记忆
- `app/tools`：工具注册、权限、幂等、审计
- `app/skills`：技能生成、版本化、动态加载
- `app/learning`：反馈学习管线
- `app/context`：Token 预算与上下文压缩
- `app/storage`：MySQL/Milvus 适配层
- `docs/sql/mysql_schema.sql`：MySQL 建表示例

### 2.2 模块职责

1. API Gateway
- 接收统一请求、调用编排层、返回统一响应。

2. Orchestrator
- 串联 Planner -> Retriever -> Executor -> Reviewer。
- 可走 LangGraph 图编排；依赖缺失时自动退化为串行执行。

3. Model Router
- 根据 `task_type + sensitivity` 从配置中路由 provider。
- 支持 fallback 顺序重试并返回是否触发降级。

4. RAG
- `IngestionPipeline`：文本分块（优先 LlamaIndex splitter）。
- `HybridRetriever`：检索并封装引用片段。

5. Memory
- 短期记忆：按会话窗口滚动保存。
- 长期记忆：带 TTL 过期机制，支持检索。

6. Tool Hub
- 工具注册、角色权限校验、幂等缓存、调用审计。

7. Skill Center
- 技能模板自动生成、版本化存储、按版本加载。

8. Learning Pipeline
- 接收显式反馈并做批处理统计，作为离线优化输入。

## 3. API 接口说明

默认前缀：`/v1`

### 3.1 同步执行：`POST /v1/agent/run`

用途：统一执行问答/自动化/分析请求。

请求示例：

```json
{
  "tenant_id": "acme",
  "user_id": "u001",
  "session_id": "s001",
  "task_type": "qa",
  "input": "Milvus 的用途是什么？",
  "context_refs": [],
  "policy": {
    "sensitivity": "low",
    "max_cost_usd": 0.5,
    "auto_execute": true,
    "require_human_review": false,
    "timeout_seconds": 60
  },
  "metadata": {
    "role": "employee"
  }
}
```

响应示例：

```json
{
  "answer": "......",
  "citations": [
    {
      "source_id": "doc-1",
      "chunk_id": "xxxx",
      "snippet": "Milvus is used for vector retrieval ...",
      "score": 1.0
    }
  ],
  "actions": [],
  "confidence": 0.84,
  "trace_id": "uuid",
  "memory_updates": [
    {"memory_type": "short", "content": "Q:..."},
    {"memory_type": "long", "content": "Preferred context ..."}
  ],
  "fallback_triggered": false
}
```

### 3.2 异步任务提交：`POST /v1/tasks/submit`

请求体：

```json
{
  "request": {
    "...": "与 /v1/agent/run 的 UnifiedRequest 相同"
  }
}
```

响应：

```json
{"task_id": "uuid"}
```

### 3.3 异步任务状态查询：`GET /v1/tasks/{task_id}`

响应示例：

```json
{
  "task_id": "uuid",
  "status": "completed",
  "trace_id": "uuid",
  "result": { "...": "UnifiedResponse" },
  "error": null
}
```

状态枚举：`queued | running | completed | failed`

### 3.4 反馈提交：`POST /v1/feedback`

请求示例：

```json
{
  "tenant_id": "acme",
  "user_id": "u001",
  "trace_id": "uuid",
  "is_correct": true,
  "score": 0.95,
  "user_edit": null,
  "tags": ["qa"]
}
```

响应示例：

```json
{
  "accepted": true,
  "stats": {
    "feedback.total": 1.0,
    "feedback.correct_ratio": 1.0
  }
}
```

### 3.5 文本知识摄取：`POST /v1/knowledge/ingest-text`

请求：

```json
{
  "tenant_id": "acme",
  "source_id": "doc-1",
  "text": "......"
}
```

响应：

```json
{"accepted": true, "chunks": 3}
```

### 3.6 技能创建：`POST /v1/skills`

请求：

```json
{
  "skill_id": "kb_qa",
  "version": "1.0.0",
  "name": "知识问答技能",
  "prompt_template": "请严格基于引用回答",
  "config": {"temperature": 0.1}
}
```

响应：`SkillSpec`

### 3.7 技能读取：`GET /v1/skills/{skill_id}/{version}`

响应：`SkillSpec`；不存在时返回 404。

### 3.8 工具回调：`POST /v1/webhook/tool-callback`

用途：接收外部系统回执，一期默认记录审计日志。

### 3.9 健康检查：`GET /health`

返回服务状态与内存指标快照。

## 4. 配置说明

### 4.1 环境变量（`.env` / 系统环境变量）

可参考 [`.env.example`](/D:/go-git/ochestrate/.env.example)。

关键项：

- `AGENT_APP_NAME`：应用名
- `AGENT_ENV`：运行环境（dev/prod）
- `AGENT_MYSQL_DSN`：MySQL 连接串
- `AGENT_MILVUS_URI`：Milvus 地址
- `AGENT_MODEL_ROUTING_PATH`：模型路由 YAML 路径
- `AGENT_MAX_CONTEXT_TOKENS`：上下文 token 预算
- `AGENT_SHORT_MEMORY_TURNS`：短期记忆窗口轮数
- `AGENT_LONG_MEMORY_DEFAULT_TTL_DAYS`：长期记忆默认保留天数
- `AGENT_SKILL_STORAGE_DIR`：技能版本存储目录
- `AGENT_AUDIT_LOG_PATH`：审计日志文件路径

### 4.2 模型路由配置（`config/model_routing.yaml`）

说明：

- `default_provider`：默认 provider
- `providers`：每个 provider 的 model/timeout/max_tokens
- `rules`：按 `task_type + sensitivity` 精确匹配
- `fallback_order`：主 provider 失败后的重试顺序

## 5. 数据库说明

### 5.1 MySQL 表结构

完整 SQL：[`docs/sql/mysql_schema.sql`](/D:/go-git/ochestrate/docs/sql/mysql_schema.sql)

主要表：

- `tenants`：租户信息
- `users`：用户与角色
- `sessions`：会话信息
- `tasks`：异步任务状态与结果
- `tool_invocations`：工具调用记录（含幂等键）
- `skill_versions`：技能版本库
- `feedback_records`：显式反馈
- `model_route_rules`：路由规则（可做 DB 动态路由）
- `audit_logs`：审计日志索引
- `knowledge_sources` / `knowledge_chunks`：知识源与分块元数据
- `long_term_memories`：长期记忆元数据

索引建议已包含在 SQL 中，重点保障：

- 多租户查询性能
- trace 查询性能
- 任务状态轮询性能

### 5.2 Milvus 集合建议（一期）

建议创建以下集合（示例）：

1. `knowledge_vectors`
- 主键：`chunk_id`
- 向量字段：`embedding`
- 标量字段：`tenant_id`, `source_id`, `domain`, `sensitivity`, `version`, `created_at`

2. `memory_vectors`
- 主键：`memory_id`
- 向量字段：`embedding`
- 标量字段：`tenant_id`, `user_id`, `tags`, `expires_at`

3. `skill_vectors`
- 主键：`skill_version_id`
- 向量字段：`embedding`
- 标量字段：`tenant_id`, `skill_id`, `version`

## 6. 部署与使用

### 6.1 本地启动

1. 安装依赖

```bash
python -m venv .venv
. .venv/Scripts/activate
pip install -e .[dev]
```

2. 启动基础设施（MySQL + Milvus）

```bash
docker compose up -d mysql etcd minio milvus
```

3. 启动服务

```bash
uvicorn app.main:app --reload
```

4. 运行测试

```bash
python -m pytest -q
```

### 6.2 快速联调流程

1. 先调用 `/v1/knowledge/ingest-text` 导入测试知识
2. 调用 `/v1/agent/run` 发起问答
3. 调用 `/v1/feedback` 提交正确性反馈
4. 调用 `/v1/tasks/submit` + `/v1/tasks/{id}` 验证异步任务链路
5. 调用 `/v1/skills` 创建技能并按版本读取

### 6.3 cURL 示例

```bash
curl -X POST http://127.0.0.1:8000/v1/knowledge/ingest-text ^
  -H "Content-Type: application/json" ^
  -d "{\"tenant_id\":\"acme\",\"source_id\":\"doc-1\",\"text\":\"Milvus is vector database.\"}"
```

```bash
curl -X POST http://127.0.0.1:8000/v1/agent/run ^
  -H "Content-Type: application/json" ^
  -d "{\"tenant_id\":\"acme\",\"user_id\":\"u1\",\"session_id\":\"s1\",\"task_type\":\"qa\",\"input\":\"Milvus做什么用？\",\"context_refs\":[],\"policy\":{\"sensitivity\":\"low\",\"max_cost_usd\":0.5,\"auto_execute\":true,\"require_human_review\":false,\"timeout_seconds\":60},\"metadata\":{\"role\":\"employee\"}}"
```
