# 企业级智能体平台使用说明（一期增强版）

本文档覆盖平台底座与增强能力：认证鉴权、任务可靠性、工具安全、技能注入、RAG 与运行部署。

## 1. 项目目标

- 构建可生产迭代的企业智能体平台。
- 支持“知识问答 + 自动化执行”双主线。
- 所有业务接口基于 Token 解析 `tenant_id/user_id/role`，不信任请求体同名字段。

## 2. 技术栈与版本

- Python 3.11+
- FastAPI
- LangChain `1.2.12`
- LangGraph `1.1.2`
- LlamaIndex
- MySQL（事务/元数据）
- Milvus（向量检索）
- Redis（异步任务队列）

## 3. 系统架构

### 3.1 分层

- 接入层：`app/api/v1`，统一 API 入口。
- 编排层：`app/orchestration`，多智能体编排（Planner/Retriever/Executor/Reviewer）。
- 模型层：`app/models`，模型路由与降级策略。
- RAG 层：`app/rag`，知识摄取和检索。
- 工具层：`app/tools`，ToolHub + 文件/网络/搜索/数据库工具。
- 技能层：`app/skills`，技能生成、版本管理、动态加载、SKILL.md 扫描。
- 记忆层：`app/memory`，短期记忆与长期记忆。
- 可靠性层：`app/workers` + `app/storage/repositories`，Redis 队列 + MySQL 状态持久化。
- 认证层：`app/auth` + `app/middleware/auth_context.py`，JWT + Refresh。

### 3.2 核心流程

1. 请求进入 API。
2. 中间件解析 Bearer Token，写入 `request.state.auth_context`。
3. 业务路由通过依赖注入获取 `AuthContext`，覆盖请求中的租户/用户字段。
4. 编排层执行多智能体流程，必要时调用 ToolHub。
5. 审计写入文件日志，并尝试持久化到 `audit_events`。

## 4. API 说明

默认前缀：`/v1`

### 4.1 认证与用户

- `POST /v1/auth/bootstrap-admin`
  - 用于初始化第一个管理员（仅在配置允许时启用）。
- `POST /v1/auth/login`
  - 入参：`tenant_id/username/password`
  - 返回：`access_token/refresh_token/token_type/expires_in/tenant_id/user_id/role/session_id`
- `POST /v1/auth/refresh`
  - 入参：`refresh_token`
  - 返回：新的 `access_token + refresh_token`
- `POST /v1/auth/logout`
  - 入参：`refresh_token`
  - 行为：吊销 Refresh Token
- `POST /v1/users`
  - 管理员接口，创建用户
- `GET /v1/users`
  - 管理员接口，查询租户下用户
- `PATCH /v1/users/{user_id}`
  - 管理员接口，更新用户角色/状态/密码

### 4.2 智能体与任务

- `POST /v1/agent/run`
  - 同步执行
  - 路由层强制使用 Token 中的 `tenant_id/user_id/role/session_id`
- `POST /v1/tasks/submit`
  - 异步提交任务，任务入 Redis 队列，状态落 MySQL
- `GET /v1/tasks/{task_id}`
  - 查询任务状态，带租户隔离校验

### 4.3 反馈、知识、技能、Webhook

- `POST /v1/feedback`
  - 反馈数据进入学习管线
- `POST /v1/knowledge/ingest-text`
  - 文本知识摄取
- `POST /v1/skills`
  - 创建技能模板
- `GET /v1/skills/{skill_id}/{version}`
  - 按版本获取技能
- `POST /v1/webhook/tool-callback`
  - 工具回调审计入库/入日志

### 4.4 健康与指标

- `GET /health`
- `GET /metrics`

## 5. 统一请求/响应对象

### 5.1 UnifiedRequest

- `tenant_id/user_id`：可传但会被忽略，最终以 Token 为准。
- `session_id/task_type/input/context_refs/policy/metadata/tool_payload/tool_overrides/skill_context_mode`

### 5.2 UnifiedResponse

- `answer/citations/actions/confidence/trace_id/memory_updates/fallback_triggered`
- `actions[]` 额外包含：
  - `error_code`
  - `audit_ref`
  - `policy_applied`

## 6. 配置说明

### 6.1 环境变量（`.env.example`）

- 项目通过环境变量读取配置，默认不会自动加载 `.env` 文件。
- PowerShell 下请使用 `$env:KEY = "VALUE"` 显式注入运行时配置。

- 数据存储：
  - `AGENT_MYSQL_DSN`
  - `AGENT_MILVUS_URI`
  - `AGENT_TASK_QUEUE_BACKEND`（`redis` 或 `memory`）
  - `AGENT_REDIS_URL`
  - `AGENT_REDIS_QUEUE_NAME`
- 认证：
  - `AGENT_JWT_SECRET`
  - `AGENT_JWT_ALGORITHM`
  - `AGENT_ACCESS_TOKEN_TTL_MINUTES`
  - `AGENT_REFRESH_TOKEN_TTL_DAYS`
  - `AGENT_AUTH_REQUIRE_ENABLED`
  - `AGENT_AUTH_BOOTSTRAP_ADMIN_ENABLED`
- 提示词与技能：
  - `AGENT_MAX_CONTEXT_TOKENS`
  - `AGENT_PROMPT_SKILL_MAX_ITEMS`
  - `AGENT_SKILL_STORAGE_DIR`
  - `AGENT_SKILL_SCAN_DIRS`
  - `AGENT_SKILL_SCAN_GLOB`

推荐数据库基线：

- `AGENT_MYSQL_DSN=mysql+pymysql://root:123456@127.0.0.1:3306/ochestrate`

### 6.2 工具安全配置（`config/tool_security.yaml`）

- `allowed_directories`：文件读写白名单目录
- `allowed_domains`：网络访问白名单域名
- `allowed_schemes`：允许协议（http/https）
- `block_private_networks`：是否阻断私网地址
- `fetch_timeout_seconds/max_fetch_chars/max_redirects`
- `db_write_protection_enabled`
- `db_confirm_field`（默认 `confirm_write`）
- `db_require_tenant_scope`：SQL 必须带租户过滤
- `max_file_size_mb`

### 6.3 模型路由配置（`config/model_routing.yaml`）

- `default_provider`：默认模型提供方。
- `providers`：定义 `local/cloud` 模型名称与超时、token 上限。
- `rules`：按 `task_type + sensitivity` 路由。
- `fallback_order`：主路由失败时的回退顺序。

### 6.4 中间件与鉴权配置

- 鉴权中间件在 `app/main.py` 中挂载：`AuthContextMiddleware`。
- 路由通过 `require_auth_context` 强制鉴权。
- `AGENT_AUTH_BOOTSTRAP_ADMIN_ENABLED` 已接入（控制是否允许初始化管理员）。
- `AGENT_AUTH_REQUIRE_ENABLED` 当前仅是配置项，尚未作为全局开关接入。

## 7. 模块功能说明

- `app/auth/service.py`
  - 密码哈希校验
  - Access/Refresh Token 签发与刷新
  - 用户创建、更新、查询
- `app/middleware/auth_context.py`
  - 解析 Bearer Token，写入请求上下文
- `app/workers/task_worker.py`
  - 消费队列任务
  - 任务状态持久化
  - 服务重启后恢复 `queued/running` 任务
- `app/tools/file_tool.py`
  - `read/write/list`
  - 支持 `json/doc/docx/xlsx/pdf/txt/csv`
  - 路径越界拦截
- `app/tools/web_tools.py`
  - Web 抓取 + 搜索
  - SSRF 防护、重定向限制、内容类型过滤
- `app/tools/database_tool.py`
  - SQL `query/execute`
  - 写操作必须显式 `confirm_write=true`
  - 可选租户范围 SQL 检查
- `app/prompts/assembly.py`
  - 分层拼装系统提示词
  - 每次注入技能清单 `name/description/skill_path`

## 9. 快速使用

### 9.1 启动

```bash
uv sync --extra dev
docker compose up -d mysql etcd minio milvus
```

PowerShell 运行时环境变量示例：

```powershell
$env:AGENT_ENV = "dev"
$env:AGENT_MYSQL_DSN = "mysql+pymysql://root:123456@127.0.0.1:3306/ochestrate"
$env:AGENT_MODEL_ROUTING_PATH = "config/model_routing.yaml"
$env:AGENT_TOOL_SECURITY_PATH = "config/tool_security.yaml"
$env:AGENT_JWT_SECRET = "change-this-secret"

# 未启动 Redis 时建议
$env:AGENT_TASK_QUEUE_BACKEND = "memory"
```

执行迁移与启动：

```powershell
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### 9.2 最小调用顺序

1. `POST /v1/auth/bootstrap-admin` 初始化管理员
2. `POST /v1/auth/login` 获取 token
3. 调用业务接口时加 Header：
   - `Authorization: Bearer <access_token>`
4. 执行：
   - `POST /v1/knowledge/ingest-text`
   - `POST /v1/agent/run`
   - `POST /v1/tasks/submit`
   - `GET /v1/tasks/{task_id}`

## 10. CI 机器人自动提交推送

仓库已增加以下工作流：

- `.github/workflows/quality-gate.yml`
  - 安装依赖并执行测试
- `.github/workflows/ci-bot-autopush.yml`
  - 质量门通过后创建 `codex/*` 机器人分支
  - 自动提交报告文件
  - 自动发起 PR

启用前置条件：

- 配置远程仓库（`origin`）
- 配置 `BOT_PUSH_TOKEN`（或使用 `GITHUB_TOKEN` 且具备写权限）
- 主分支开启保护策略，禁止直接推送

## 11. 开发者深入阅读路径

为了避免“会用但不会改”，建议按以下顺序阅读文档并动手验证：

1. 本文档（`docs/中文使用说明.md`）
   - 目标：先建立系统全貌、接口边界、部署与配置认知。
2. 架构文档（`docs/architecture.md`）
   - 目标：理解模块分层与核心链路（编排、存储、工具、可观测）。
3. 开发手册（`docs/开发手册.md`）
   - 目标：按“为什么这样设计 + 实际怎么改 + 改完如何验证”开展二次开发。

推荐实践节奏：

- 第一步：完整跑通一次本地启动与最小调用链路。
- 第二步：按开发手册完成一个小改动（如新增工具或新增 API 字段）。
- 第三步：执行 `python -m pytest -q` 并做关键接口回归验证。
